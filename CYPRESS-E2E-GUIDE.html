1 What is E2E Testing?

End-to-End (E2E) testing simulates a real user interacting with your app in a real browser. It verifies the entire flow from start to finish.

Test TypeWhat it testsExample
Unit TestIndividual functionsDoes add(2, 3) return 5?
Integration TestComponents togetherDoes LoginForm call the API correctly?
E2E TestEntire user journeyCan a user log in and see the dashboard?
/ E2E \ ← Few but critical (slow, high confidence) /----------\ / Integration \ ← Medium amount (moderate speed) /----------------\ / Unit Tests \ ← Many and fast (low-level logic) /--------------------\

Why E2E Testing?

BenefitDescription
Catches real bugsTests what users actually experience
Tests the full stackFrontend + API + routing + state all together
Confidence to deployIf E2E tests pass, the app works
Visual proofScreenshots and videos show exactly what happened

What happens on first open:

  1. Cypress downloads its browser (Electron)
  2. Creates cypress/e2e/ — your test files
  3. Creates cypress/fixtures/ — test data (JSON)
  4. Creates cypress/support/ — custom commands
  5. Creates cypress.config.js in project root

7 Writing Your First Test

Test file structure

// cypress/e2e/my-test.cy.js

describe('Feature Name', () => {
  // Runs BEFORE each test
  beforeEach(() => {
    cy.visit('/');
  });

  it('should do something', () => {
    cy.get('selector').should('be.visible');
  });
});
BlockPurposeRuns when
describe()Groups related tests—
it()One individual testOnce
beforeEach()Setup before each testBefore every it()
afterEach()Cleanup after each testAfter every it()
before()One-time setupOnce before all tests
after()One-time cleanupOnce after all tests

Real example — Login page test

describe('Login Page', () => {
  beforeEach(() => {
    cy.visit('/');
  });

  it('displays the login form', () => {
    cy.get('[data-cy="email-input"]').should('be.visible');
    cy.get('[data-cy="password-input"]').should('be.visible');
    cy.get('[data-cy="submit-btn"]').should('contain.text', 'Sign In');
    cy.screenshot('login-form-rendered');
  });
});

9 Selecting Elements — data-cy Attributes

BAD — Fragile selectors
// Breaks when styling changes
cy.get('.bg-blue-500.rounded-lg')

// Breaks when text changes
cy.contains('Log In')
GOOD — Resilient selectors
// Never changes accidentally
cy.get('[data-cy="submit-btn"]')

// Purpose-built for testing
cy.get('[data-cy="email-input"]')

How to add data-cy in React

// In your React component
<form data-cy="login-form">
  <input data-cy="email-input" type="email" />
  <input data-cy="password-input" type="password" />
  <button data-cy="submit-btn">Sign In</button>
</form>
SelectorResilient?Why
.btn-primaryNoCSS classes change with styling
#submitSomewhatIDs can be reused or renamed
contains('Sign In')NoText changes with i18n
[data-cy="submit-btn"]YesPurpose-built for testing

10 API Mocking with cy.intercept()

cy.intercept() catches network requests and returns fake responses. No real backend needed!

Your App cy.intercept() Real Server | | | |--- POST /api/login --> | | | | (catches request) | | | (returns fake data) | |<-- { token: '...' } --| | | | (never reaches here) |

Basic pattern

// 1. Set up intercept BEFORE the action
cy.intercept('POST', '/api/auth/login', {
  statusCode: 200,
  body: { token: 'fake-jwt-token', user: { name: 'Alice' } },
}).as('loginRequest');

// 2. Perform the action
cy.get('[data-cy="submit-btn"]').click();

// 3. Wait for the request
cy.wait('@loginRequest');

// 4. Assert
cy.url().should('include', '/home');

Different scenarios

// SUCCESS (200)
cy.intercept('POST', '/api/auth/login', {
  statusCode: 200,
  body: { token: 'fake-jwt-token' },
});

// ERROR (401)
cy.intercept('POST', '/api/auth/login', {
  statusCode: 401,
  body: { message: 'Invalid credentials' },
});

// SLOW RESPONSE (test loading state)
cy.intercept('POST', '/api/auth/login', {
  statusCode: 200,
  body: { token: 't' },
  delay: 2000,  // 2 second delay
});

// NETWORK ERROR
cy.intercept('POST', '/api/auth/login', {
  forceNetworkError: true,
});

Inspect request payload

cy.wait('@loginReq').its('request.body').should('deep.equal', {
  email: 'test@email.com',
  password: 'mypassword',
});

11 Fixtures — External Test Data

Create a fixture file

// cypress/fixtures/users.json
{
  "validUser": {
    "email": "alice@example.com",
    "password": "password123"
  },
  "apiResponse": {
    "token": "fake-jwt-token",
    "user": {
      "name": "Alice Johnson",
      "email": "alice@example.com"
    }
  }
}

Load fixtures in tests

describe('Login with fixtures', () => {
  let users;

  beforeEach(() => {
    cy.fixture('users').then((data) => {
      users = data;
    });
    cy.visit('/');
  });

  it('logs in with fixture data', () => {
    cy.intercept('POST', '/api/auth/login', {
      statusCode: 200,
      body: users.apiResponse,
    });

    cy.get('[data-cy="email-input"]').type(users.validUser.email);
    cy.get('[data-cy="password-input"]').type(users.validUser.password);
    cy.get('[data-cy="submit-btn"]').click();
    cy.url().should('include', '/home');
  });
});

12 Custom Commands

Custom commands extend cy with reusable functions.

cypress/support/commands.js

// cy.login() — Full UI login with intercepted API
Cypress.Commands.add('login', (email, password) => {
  cy.intercept('POST', '/api/auth/login', {
    statusCode: 200,
    body: {
      token: 'fake-jwt-token',
      user: { name: 'Alice Johnson', email },
    },
  }).as('loginRequest');

  cy.visit('/');
  cy.get('[data-cy="email-input"]').type(email);
  cy.get('[data-cy="password-input"]').type(password);
  cy.get('[data-cy="submit-btn"]').click();
  cy.wait('@loginRequest');
});

// cy.loginByApi() — Skip UI, set localStorage (FASTER!)
Cypress.Commands.add('loginByApi', (email = 'test@example.com') => {
  const user = { name: 'Alice Johnson', email };
  localStorage.setItem('token', 'fake-jwt-token');
  localStorage.setItem('user', JSON.stringify(user));
  cy.visit('/home');
});

Usage in tests

Without custom commands (repetitive)
cy.intercept(...);
cy.visit('/');
cy.get('[data-cy="email-input"]').type(...);
cy.get('[data-cy="password-input"]').type(...);
cy.get('[data-cy="submit-btn"]').click();
cy.wait('@loginRequest');
With custom commands (clean)
// Full UI login
cy.login('alice@example.com', 'pass123');

// Or skip UI entirely (fast)
cy.loginByApi('alice@example.com');
CommandSpeedWhen to use
cy.login(email, pass)Slow (~2s)When testing the login flow itself
cy.loginByApi(email)Fast (~0.2s)When you just need to BE logged in

14 Testing a Full Multi-Page Flow

The app flow

Login (/) → Home (/home) → Profile (/profile) → Logout → Login (/)

Complete journey test

describe('Full App Flow', () => {
  it('completes the entire journey', () => {
    // 1. Login page
    cy.visit('/');
    cy.get('[data-cy="login-form"]').should('be.visible');
    cy.screenshot('flow-1-login-page');

    // 2. Mock API and log in
    cy.intercept('POST', '/api/auth/login', {
      statusCode: 200,
      body: {
        token: 'fake-jwt-token',
        user: { name: 'Alice Johnson', email: 'alice@example.com' },
      },
    }).as('loginRequest');

    cy.get('[data-cy="email-input"]').type('alice@example.com');
    cy.get('[data-cy="password-input"]').type('password123');
    cy.get('[data-cy="submit-btn"]').click();
    cy.wait('@loginRequest');

    // 3. Home page
    cy.url().should('include', '/home');
    cy.get('[data-cy="welcome-message"]').should('contain.text', 'Alice Johnson');
    cy.screenshot('flow-2-home-page');

    // 4. Navigate to profile
    cy.get('[data-cy="nav-profile"]').click();
    cy.url().should('include', '/profile');
    cy.screenshot('flow-3-profile-page');

    // 5. Logout
    cy.get('[data-cy="nav-logout"]').click();
    cy.url().should('eq', Cypress.config().baseUrl + '/');
    cy.screenshot('flow-5-logged-out');

    // 6. Verify localStorage cleared
    cy.window().then((win) => {
      expect(win.localStorage.getItem('token')).to.be.null;
      expect(win.localStorage.getItem('user')).to.be.null;
    });
  });
});

16 CI/CD with GitHub Actions

# .github/workflows/cypress.yml
name: Cypress E2E Tests

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  cypress-run:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Use Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run Cypress tests
        uses: cypress-io/github-action@v6
        with:
          build: npm run build
          start: npm run dev
          wait-on: 'http://localhost:5173'
          browser: chrome

      - name: Upload screenshots on failure
        uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: cypress-screenshots
          path: cypress/screenshots

      - name: Upload videos always
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: cypress-videos
          path: cypress/videos

18 Common Errors & Fixes

Error: "Timed out retrying: expected to find element"

Cause: Element doesn't exist or hasn't rendered yet.

// Fix: increase timeout
cy.get('[data-cy="submit-btn"]', { timeout: 10000 }).should('be.visible');
Error: "cy.visit() failed trying to load"

Cause: Dev server not running.

Fix: Use npm run test:e2e instead of npm run cy:run.

Error: SIGKILL — Test Runner unexpectedly exited

Cause: Out of memory.

// Fix in cypress.config.js:
numTestsKeptInMemory: 0

// Or disable video:
video: false
Error: "Port 5173 is in use"

Cause: Previous dev server still running.

# Kill processes on port 5173
lsof -ti:5173 | xargs kill -9
Error: Intercept not catching requests

Cause: cy.intercept() called AFTER the request.

// CORRECT: intercept BEFORE the action
cy.intercept('POST', '/api/login', { ... }).as('login');
cy.get('button').click();
cy.wait('@login');

19 Best Practices

1. Use data-cy for selectors
<button data-cy="submit-btn">Submit</button>
2. One assertion concept per test
it('shows error on invalid credentials', () => { ... });
it('shows loading state', () => { ... });
it('redirects on success', () => { ... });
3. Use beforeEach for common setup
beforeEach(() => {
  cy.loginByApi('alice@example.com');
});
4. Use loginByApi for speed (skip UI when possible)

Only test login UI in login.cy.js. Everywhere else, use the fast approach.

5. Never use cy.wait(ms) for timing
// BAD:  cy.wait(3000);
// GOOD: cy.get('[data-cy="result"]').should('be.visible');
// GOOD: cy.wait('@apiRequest');
6. Keep tests independent

Each test should work on its own. Never depend on another test running first.

7. Add screenshots at key points
cy.screenshot('descriptive-name');
8. Add .gitignore for generated files
cypress/videos/
cypress/screenshots/
